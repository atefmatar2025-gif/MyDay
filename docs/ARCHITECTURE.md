# البنية التقنية والقرارات الهندسية

## الطبقات

```
┌──────────────── Presentation (app/ui) ────────────────┐
│ Compose screens + ViewModels (MVVM, StateFlow)         │
└───────────────┬───────────────────────────────────────┘
                │
┌───────────────▼──────────── Domain (app/domain) ──────┐
│ TaskInteractor · AssistantService · FocusTimer ·        │
│ DataManager   (كل تغيير للحالة يمر من هنا)             │
└──────┬─────────────────┬──────────────────┬───────────┘
       │                 │                  │
┌──────▼─────┐  ┌────────▼────────┐  ┌──────▼──────────────┐
│ Data       │  │ Notification    │  │ core (Kotlin خالص)   │
│ Room/DAOs  │  │ AlarmScheduler  │  │ Intelligence Engine │
│ Repos      │  │ ReminderSched.  │  │ Scheduling Engine   │
│ DataStore  │  │ Receivers/Svc   │  │ Recurrence/Alarm    │
│ Backup     │  │ Workers/Widget  │  │ timing, Parser,     │
└────────────┘  └─────────────────┘  │ Stats, Backup fmt   │
                                     └─────────────────────┘
```

- **core** وحدة Gradle مستقلة (`kotlin("jvm")`) لا تعرف Android ولا Room ولا الواجهات. محرك الذكاء ومحرك الجدولة يعملان على نماذج نطاق بسيطة، ولذلك تُختبر على JVM مباشرة.
- **Repository Pattern**: الواجهات لا تلمس DAOs؛ المستودعات تجمع الجداول (المهام + التصنيفات + الوسوم + الاعتماديات) إلى نموذج `Task` واحد.
- **TaskInteractor** هو المكان الوحيد الذي يغيّر المهام، فيضمن دائماً: (1) إعادة جدولة التنبيهات، (2) كتابة سجل الإنجاز، (3) تحديث الودجت.

## قرارات موثّقة

| القرار | السبب |
|---|---|
| **حقن تبعيات يدوي** (`AppContainer`) بدل Hilt | المتطلب سمح بـ«Hilt أو آلية مناسبة». حاوية صريحة تقلل معالجات الشفرة (Room فقط عبر KSP) وتُبقي البناء أبسط وأكثر استقراراً، مع نفس فصل الطبقات. التحويل إلى Hilt لاحقاً مباشر. |
| أوقات المهام تُخزّن **بتوقيت الساعة المحلية** (LocalDateTime) | المهمة «الساعة 8 صباحاً» تبقى 8 صباحاً بعد السفر أو تغيير المنطقة الزمنية – كما في تطبيقات المنبّه. يُعاد تحويلها إلى لحظة زمنية عند كل جدولة. |
| مهمة متكررة = **صف واحد** يتقدّم إلى الموعد التالي عند الإكمال | أبسط وأمتن من توليد صفوف مستقبلية؛ كل إكمال يُسجَّل في ذاكرة الإنجاز بشكل منفصل. التقويم يعرض المواعيد المستقبلية حسابياً. |
| **ذاكرة الإنجاز** جدول مستقل بلا مفتاح أجنبي على المهام | يبقى السجل كاملاً بعد تعديل المهمة أو حذفها (متطلب صريح). |
| قاعدة التكرار نص مضغوط بإصدار (`v1;F=WEEKLY;I=1;D=1,4`) | قيمة واحدة منظمة وقابلة للترحيل، وليست JSON عشوائياً كبديل لقاعدة البيانات. |
| الإعدادات في جدول Room (صف واحد) + DataStore لحالة خفيفة | الإعدادات تُنسخ احتياطياً مع البيانات؛ DataStore لحالة مؤقت التركيز وآخر نسخة احتياطية. |
| **لا fallbackToDestructiveMigration** | ترحيل ناقص يجب أن يفشل في الاختبار بدل مسح بيانات المستخدم. `exportSchema = true` + `MigrationTest`. |
| رسوم بيانية بـ Canvas بدل مكتبة خارجية | لا تبعيات مهجورة، دعم RTL ووصف TalkBack لكل رسم. |
| خط IBM Plex Sans Arabic مضمّن | خط عربي احترافي يعمل دون إنترنت (رخصة SIL OFL – `assets/licenses`). |
| الهجري من `java.time.chrono.HijrahDate` (أم القرى) + تعديل ±2 يوم | مكتبة موثوقة مدمجة في أندرويد 8+، دون تبعية إضافية، مع مراعاة اختلاف الرؤية. |
| الواجهة RTL دائماً + لغة عربية مفروضة على الـ Activity | المتطلب: واجهة عربية أصلية. كل النصوص في `strings.xml`، ونصوص المحرك تمر عبر كائن `Ar` – إضافة الإنجليزية = `values-en/strings.xml` + تنفيذ مقابل لـ `Ar`. |
| السحب في خريطة اليوم عبر `detectDragGesturesAfterLongPress` بخطوات 15 دقيقة، مع تأكيد | تفاعل مستقر في Compose؛ التأكيد يمنع النقل بالخطأ. المهام المتكررة لا تُسحب (نقلها يغيّر السلسلة كلها). |
| أصوات التركيز مولّدة رقمياً (ضجيج أبيض/وردي/بني) | أصوات «أصلية» دون ملفات تحتاج ترخيصاً. تعمل أثناء فتح الشاشة فقط (لا خدمة أمامية بلا مبرر). |

## DAYFLOW INTELLIGENCE ENGINE

```kotlin
interface AssistantEngine {
    val displayName: String
    val isLanguageModel: Boolean          // false للمحرك الحالي – الواجهة تقول ذلك صراحة
    fun answer(query: String, context: AssistantContext): AssistantReply
    fun dailyInsight(context: AssistantContext): String?
}
```
- `RuleBasedAssistantEngine` (المرحلة الأولى): `IntentClassifier` (تطبيع عربي + كلمات مفتاحية مرتبة) ← معالج لكل نية يعتمد على `TaskRanker` و`ConflictDetector` و`DayPlanner` و`ProductivityStats`.
- **لا يغيّر البيانات أبداً**: يعيد `AssistantAction` (ابدأ، افتح، راجع الخطة) تظهر أزراراً، وكل تغيير يحتاج ضغطة/تأكيد المستخدم.
- **إضافة نموذج لغوي محلي لاحقاً**: نفّذ `AssistantEngine` (مثلاً `LocalLlmEngine`) واستخدم `AssistantContext` كسياق مُؤرِّض، ثم بدّل سطراً واحداً في `AppContainer.assistantEngine`.

### خوارزمية «ماذا أفعل الآن؟» (TaskRanker)
الأولوية (25–100) + قرب الموعد النهائي (حتى +40) + مجدولة الآن (+20) + قيد التنفيذ (+15) + تناسب الوقت المتاح حتى الالتزام التالي (±10) + التأجيلات السابقة (حتى +15) + فتح الطريق لمهام معتمدة (+5 لكل منها).
تُستبعد: المغلقة، المحجوبة باعتمادية مفتوحة، الرئيسية ذات الفرعيات المفتوحة، المواعيد الثابتة، ومهام الأيام القادمة. يحترم أوقات الراحة وخارج ساعات اليوم والموعد الوشيك (≤10 دقائق).

### خوارزمية «أنقذ يومي» (DayPlanner)
1. جمع مهام اليوم المفتوحة + المتأخرة من أيام سابقة + غير المؤرخة عالية الأولوية.
2. نافذة التخطيط: من max(الآن، بداية اليوم) إلى وقت النوم.
3. الوقت المشغول = المواعيد الثابتة (+فاصل) + أوقات الراحة ← فترات فراغ.
4. الترتيب: المستحقة اليوم أولاً، ثم الأولوية، ثم الموعد، ثم الأقصر؛ والاعتماديات قبل المعتمِد.
5. توزيع جشع على أقرب فراغ؛ المهام الأطول من «أقصى مدة للجزء» تُقسَّم (أجزاء ≥ 25 دقيقة).
6. ما لا يتسع يُعرض بصدق: «قد لا يمكن إنجازها» (مهمة/مستحقة) أو «مقترح تأجيلها» (البقية).
الخطة معاينة فقط؛ عند الاعتماد تُنقل المهام المرنة، وتتحول المقسّمة إلى مهام فرعية، وتُؤجَّل المقترحات التي أبقى المستخدم علامتها، وتُحفظ الخطة في `daily_plans`.
